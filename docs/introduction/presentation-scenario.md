> **발표 목적**: 현재 4개 부서에서 운영 중인 시스템의 전사 확산을 자연스럽게 유도

> **톤**: "우리가 이미 만들었고, 효과가 검증됐다. 같이 쓰면 더 강력해진다."
> **분량**: 약 19슬라이드 (발표 20-25분)

## Slide 2: 우리가 매일 겪는 문제 (Problem Statement)

**제목: "익숙한 풍경들"**

왼쪽(AS-IS)에 일상적 문제 상황들을 나열:

| 상황 | 현실 |
|------|------|
| "이 프로젝트에 SW 엔지니어 몇 명 투입되고 있어?" | → Excel 파일 찾기, 버전 확인, 수작업 취합 |
| "다음 분기에 우리 팀 여유 인력 있어?" | → 각 PM한테 개별 문의, 답변 대기 |
| "지난달 NPI에 실제 얼마나 투입됐어?" | → SharePoint 리스트 다운로드, 피벗 테이블 |
| "리소스가 부족하다는 근거 데이터 좀 보여줘" | → ... (침묵) |

> **발표자 노트**: "혹시 이런 상황 겪어보신 분?" 청중 공감 유도. 특히 마지막 항목에서 잠깐 멈추며 공감 형성.

## Slide 3: 이 문제가 왜 지금 중요한가 (Why Now)

**제목: "더 이상 Excel로는 안 되는 이유"**

- **프로젝트 복잡도 증가**: EUV 프로그램 확대, NPI/ETO/CIP 동시 진행
- **Cross-functional 협업 증가**: 한 엔지니어가 2-3개 프로젝트에 동시 투입
- **인력 확보 경쟁**: 리소스 부족을 "느낌"이 아닌 "데이터"로 증명해야 함
- **비용 투명성 요구**: Direct vs. Indirect 비용 구분, GAAP 준수 필요성 증가

핵심 메시지 박스:
> "데이터 없는 리소스 요청은 승인되지 않는다.
> 데이터 있는 리소스 요청은 거절하기 어렵다."

> **발표자 노트**: "특히 PM분들께서 추가 인력을 요청할 때, '바쁘다'만으로는 부족합니다. 지난 6개월간 팀원들의 FTE가 1.0을 초과했다는 데이터가 있으면 이야기가 달라집니다."

## Slide 4: 설계 철학 - 넣는 건 쉽게, 분류는 상세히

**제목: "입력은 1분, 효과는 조직 전체로"**

핵심 설계 원칙:
> **"넣는 것은 가능한 쉽게, 분류는 상세히"**

이 원칙이 왜 중요한가 - 기존 SharePoint의 악순환:

```
기존 SharePoint의 악순환
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
엔지니어: "입력하기 귀찮아요"
    ↓
엔지니어: "이거 어디에 쓰이는지도 모르겠어요"
    ↓
엔지니어: "왜 해야 하는 건데요?"
    ↓
매니저: (설득할 근거가 없음... 실시간 결과물이 없으니까)
    ↓
데이터 품질 저하 → 어쩌다 한 번 취합 → 프로젝트 계획에 반영 안 됨
    ↓
"그래서 이거 왜 하는 건데요?" (반복)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Operation Board의 선순환:

```
Operation Board의 선순환
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
엔지니어: "30초면 끝나네" (2-3 클릭)
    ↓
시스템: 자동으로 상세 분류 (비용 버킷, 활동 유형, 프로젝트 카테고리)
    ↓
대시보드: 실시간으로 결과가 보임 (내 FTE, 팀 현황, 프로젝트 상태)
    ↓
매니저: "너희가 매일 1분만 투자하면, 이런 결과를 볼 수 있어"
    ↓
데이터 품질 향상 → 리소스 의사결정 근거 확보 → 실제 프로젝트 계획에 반영
    ↓
"아, 이래서 넣는 거구나" (자발적 참여)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

핵심 메시지 박스:
> **매니저가 팀원에게 말할 수 있게 됩니다:**
> "하루 1분만 투자해줘. 그 1분이 모이면
> 우리 팀에 사람이 더 필요하다는 걸 데이터로 증명할 수 있어.
> 그리고 네가 넣는 순간 바로 결과가 보여."

왜 기존에는 이 말이 안 됐는가:
| | 기존 SharePoint | Operation Board |
|---|---|---|
| **입력 후 결과** | 없음. 매니저가 취합할 때까지 블랙홀 | 즉시. 내 대시보드에 실시간 반영 |
| **데이터 활용** | 어쩌다 한 번 피벗 테이블 | 매일 자동 집계, 리포트, 트렌드 |
| **프로젝트 반영** | 안 됨 | 리소스 계획에 직접 연동 |
| **입력 동기** | "시킨다니까..." | "내 현황이 바로 보이니까" |

> **발표자 노트**: "기존에 매니저분들이 팀원한테 워크로그 넣으라고 하면, '이거 넣기도 힘든데 어디다 쓰이는지도 모르겠고, 왜 해야 하는 거예요?' 라는 질문에 답하기 어려우셨을 겁니다. 실시간으로 보여주는 게 없으니까요. 이 시스템은 그 질문에 대한 답입니다. 넣는 건 30초, 그리고 넣는 순간 바로 결과가 보입니다. 매니저분들도 '하루 1분만 써줘, 대신 이런 결과가 나와'라고 당당하게 말할 수 있게 됩니다."

## Slide 5: 해결책 소개 (Solution Overview)

**제목: "Project Operation Board - 한 눈에 보는 엔지니어링 리소스"**

시스템의 3가지 핵심 가치를 큰 아이콘과 함께:

| 핵심 가치 | 설명 |
|-----------|------|
| **실시간 가시성** (Real-time Visibility) | 누가, 어디에, 얼마나 투입되는지 즉시 확인 |
| **데이터 기반 의사결정** (Data-Driven Decisions) | 과거 실적 + 미래 계획을 한 화면에서 비교 |
| **제로 수작업** (Zero Manual Work) | Excel 취합, 피벗 테이블, 수동 보고서 불필요 |

아래에 한 줄:
> "이미 4개 부서, 약 00명이 매일 사용하고 있습니다."

> **발표자 노트**: "이건 계획이 아닙니다. 이미 동작하고 있는 시스템입니다."

## Slide 6: 핵심 기능 1 - 개인 대시보드 (My Dashboard)

**제목: "30초 만에 파악하는 나의 리소스 현황"**

실제 My Dashboard 스크린샷 또는 목업:

- **My FTE 현황**: 이번 달 프로젝트별 투입 비율 시각화
  - 계획(Planned) vs 실적(Actual) 비교 바 차트
  - Product 업무 vs. Support 업무 비율
  - FTE > 1.0이면 빨간색으로 경고 (과부하 신호)
- **주간 워크로그 요약**: 이번 주 기록 현황
- **내 프로젝트 마일스톤**: 다가오는 Gate Review 일정

강조 포인트:
> "팀원 본인이 자기 상태를 먼저 알 수 있어야
> 매니저에게도 정확한 정보가 올라갑니다."

> **발표자 노트**: "기존에는 팀원들이 자신의 투입률을 정확히 모릅니다. 여기서는 로그인하자마자 바로 보입니다."

## Slide 7: 핵심 기능 2 - 워크로그 (Smart Timesheet + AI 입력 보조)

**제목: "클릭으로도, 말로도 입력할 수 있는 워크로그"**

Before vs After 비교:

| | 기존 (SharePoint) | Operation Board |
|---|---|---|
| **입력 횟수** | 8-10 클릭 | 2-3 클릭 또는 자연어 한 줄 |
| **소요 시간** | 2-3분 | 30초 이내 |
| **일일 기록률** | ~60% | 90%+ 목표 |
| **데이터 활용** | 수동 다운로드 → 피벗 | 실시간 자동 집계 |

### 입력 방법 1: 클릭 방식 (기본)
- **스마트 디폴트**: 주 프로젝트, 최근 Activity 자동 선택
- **지난주 복사**: 반복 업무는 원클릭 복사
- **미팅 분류**: 의사결정/정보공유/피드백 등 회의 유형 구분
- **긴급업무/출장 플래그**: 돌발 업무 추적 가능

### 입력 방법 2: AI 자연어 입력 (보조)

```
┌────────────────────────────────────────────────┐
│  AI 워크로그 입력                        [AI 탭] │
├────────────────────────────────────────────────┤
│                                                │
│  오늘 뭘 하셨나요? 자유롭게 적어주세요:          │
│  ┌──────────────────────────────────────────┐  │
│  │ "오전에 OQC 프로젝트 미팅하고             │  │
│  │  오후에 NPI 407056 설계 작업함"           │  │
│  └──────────────────────────────────────────┘  │
│                                                │
│  [AI 분석하기]                                  │
│                                                │
│  ── AI 분석 결과 ──────────────────────────────  │
│                                                │
│  ✅ 항목 1:                                     │
│     프로젝트: OQC Infra (자동 매핑)              │
│     활동: MEET (미팅)                           │
│     시간: 4h (오전 → 4시간)                     │
│                                                │
│  ✅ 항목 2:                                     │
│     프로젝트: ACM NPI 407056 (자동 매핑)         │
│     활동: DESIGN (설계)                         │
│     시간: 4h (오후 → 4시간)                     │
│                                                │
│  [수정] [저장하기]                               │
│                                                │
└────────────────────────────────────────────────┘
```

AI 입력의 핵심 포인트:
| 특징 | 설명 |
|------|------|
| **자연어 인식** | "오전에", "오후에", "잠깐" 등 일상 표현을 시간으로 변환 |
| **프로젝트 자동 매핑** | 프로젝트명, IO 코드, 키워드로 정확한 프로젝트 연결 |
| **활동 자동 분류** | "미팅" → MEET, "설계" → DESIGN, "테스트" → TEST 자동 매칭 |
| **한 줄에 여러 항목** | 하루 업무를 한 문장으로 쓰면 여러 워크로그로 분리 |
| **수정 가능** | AI 결과를 확인하고 틀린 부분만 수정 후 저장 |

> **핵심 메시지:**
> "프로젝트 코드 기억 안 나도 됩니다. 드롭다운 찾을 필요도 없습니다.
> 그냥 오늘 뭘 했는지 한 줄로 적으면, AI가 알아서 정리해줍니다."

> **발표자 노트**: "워크로그 입력이 번거로우면 아무도 안 합니다. 그래서 두 가지 방법을 제공합니다. 클릭이 편한 분은 2-3번 클릭으로, 타이핑이 편한 분은 '오전에 미팅하고 오후에 개발함' 이렇게 한 줄 쓰면 됩니다. AI가 프로젝트와 활동 유형을 자동으로 매핑합니다. 물론 AI 결과가 틀리면 수정할 수 있고, 맞으면 바로 저장하면 됩니다. 입력의 허들을 최대한 낮추는 게 목표입니다."

## Slide 8: 핵심 기능 3 - 리소스 매트릭스 (Resource Matrix)

**제목: "전체 조직의 리소스 배치를 한 화면에서"**

Resource Matrix 스크린샷 또는 목업:

- **행(Y축)**: 팀원 이름
- **열(X축)**: 월별 (12개월+)
- **셀**: 프로젝트별 FTE 배분 (색상 코딩)
- **TBD 포지션**: 아직 배정 안 된 자리가 노란색으로 표시

이 화면이 보여주는 것:
1. 누가 어떤 프로젝트에 얼마나 투입되는지
2. 과배정(>1.0 FTE) 된 사람이 누구인지
3. 미래 3-6개월의 리소스 계획
4. 채용이 필요한 빈 자리(TBD)가 어디인지

> **발표자 노트**: "이 화면 하나로 FM은 팀의 리소스 현황을, PM은 프로젝트의 인력 현황을 동시에 볼 수 있습니다. 기존에는 이걸 보려면 Excel 파일 3-4개를 열어야 했습니다."

## Slide 9: 핵심 기능 4 - PM을 위한 리소스 증명 (FTE Analytics)

**제목: "리소스 부족, 이제 데이터로 증명합니다"**

PM 관점의 시나리오:

```
시나리오: "우리 팀에 SW 엔지니어 1명이 더 필요합니다"

기존 방식:
PM: "팀이 바빠요. 사람이 부족해요."
매니저: "다 바쁘다고 하는데, 근거가 뭐야?"
PM: "... (Excel 정리하러 감)"

Operation Board 방식:
PM: (화면 공유)
 "지난 6개월간 SW팀 평균 FTE가 1.15입니다.
  매월 팀원당 평균 12시간의 초과 근무가 발생했고,
  향후 3개월 내 NPI 2건이 추가 예정입니다.
  현재 TBD 포지션 1건이 미배정 상태입니다."
매니저: "이 데이터면 충분하네. 채용 프로세스 시작하자."
```

핵심 데이터 포인트 시각화:
- **Planned vs Actual FTE** 트렌드 차트 (6개월)
- **FTE > 1.0 초과 빈도** 히트맵
- **미배정 TBD 포지션** 목록

> **발표자 노트**: "이것이 PM분들에게 가장 강력한 도구입니다. '감'이 아니라 '팩트'로 이야기할 수 있게 됩니다."

---

## Slide 10: 핵심 기능 5 - 미래 리소스 포캐스팅 (Resource Forecasting)

**제목: "3개월 후 우리 팀은 어떤 모습일까?"**

12개월 전방 계획 기능 소개:

| 기능 | 설명 |
|------|------|
| **월별 FTE 배분** | 프로젝트별 × 역할별 × 월별 투입 계획 |
| **TBD 포지션 관리** | 아직 채용 안 된 자리를 미리 계획에 반영 |
| **역할 기반 계획** | "SW Engineer 1명" 같은 포지션 단위 계획 |
| **동적 Capacity 계산** | 한국 공휴일, 휴가 자동 반영한 가용 시간 |

예시 뷰:

```
2026년 Q2 리소스 현황 (Control Engineering)
─────────────────────────────────────────────
이름          4월    5월    6월    상태
─────────────────────────────────────────────
김철수        0.8    0.8    0.5    정상

## Slide 11: 핵심 기능 6 - 비용 자동 분류 (Cost Allocation)

**제목: "일하는 사람은 쉽게, 관리하는 사람은 정확하게"**

2단 구조 설명:

**사용자(엔지니어)가 하는 일:**
- 프로젝트 선택 → 활동 선택 → 시간 입력 (끝)

**시스템이 자동으로 하는 일:**
- Context(부서, 프로젝트 유형, 활동)를 분석
- 4가지 비용 버킷으로 자동 분류:
  - Direct Product (자본화 가능, NPI/ETO R&D)
  - Direct Project (고객 프로젝트)
  - Indirect (Field Support, 유지보수)
  - Overhead (교육, 행정, 휴가)
- 95%+ 정확도, 분류 근거 추적 가능

비용 분류 결과 예시 차트:
```

Direct Product  ████████████████░░░░  68%  (목표: 60-70%)  ✓
Direct Project  ███░░░░░░░░░░░░░░░░░  12%  (목표: 10-15%)  ✓

> **발표자 노트**: "엔지니어는 복잡한 비용 코드를 알 필요가 없습니다. 그냥 자기 일을 기록하면, 시스템이 알아서 분류합니다. Finance 팀이 필요로 하는 비용 투명성을 사용자 부담 없이 확보할 수 있습니다."

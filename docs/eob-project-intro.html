Engineering teams across the EUV Program track time, allocate resources, and reconcile inter-company costs using a patchwork of disconnected tools. The result is unreliable data, wasted effort, and slow financial cycles.

Before — Fragmented Workflow

  • Worklogs scattered across SharePoint lists, PCAS Excel files, and personal spreadsheets with no unified view
  • Resource allocation decided in meetings then maintained in email threads — no live capacity dashboard
  • Inter-company billing (VSS/SUN/LOCAL_KR) reconciled manually each quarter with significant error margins
  • Cost classification done by hand — engineers guess whether their work is CAPEX-eligible or overhead
  • No visibility into plan vs. actual — over-allocations discovered too late to correct
  • Monthly compliance: managers chase engineers for missing time entries via email for weeks

After — Operation Board

  • Single web application for all worklog entry, resource planning, and cost reporting across 3 entities
  • 12-month resource matrix with real-time plan vs. actual FTE comparison and variance heatmaps

  • Monthly completion tracking with automated reminders — dashboard shows gaps in real time

Platform Capabilities

Each capability addresses a specific pain point in engineering resource management. Together they form a closed loop from daily time entry through financial reporting.

1

AI-Powered Worklog Entry

Purpose: Reduce time-entry friction to near zero so engineers actually fill in their logs consistently and accurately.

The single biggest failure mode in resource tracking is missing data. Engineers find time entry tedious, so they skip days, batch-enter inaccurate estimates at month-end, or abandon the system entirely. Operation Board solves this with an AI parser that accepts natural language input in English or Korean.

Type "3h pump controller design, 1.5h PTM with Tumalo team, 0.5h code review" and the system extracts structured entries with project resolution, activity classification, and duration breakdown. The underlying LLM (Groq Llama 3.3 or Google Gemini 2.0 Flash) handles abbreviations, Korean text, and fuzzy project name matching with confidence scoring.

  • Natural language parsing with automatic project/activity/duration extraction
  • Fuzzy entity matching using Jaro-Winkler similarity (handles misspellings and aliases)
  • Calendar UI for visual entry with day/week/month views and bulk copy for recurring meetings
  • Monthly completion dashboard: shows exactly which days are missing entries per engineer
  • CSV export for compliance reporting and external system integration
2

Resource Matrix — 12-Month FTE Planning Grid

Purpose: Give managers real-time visibility into who is working on what, and whether reality matches the plan.

The Resource Matrix is a pivot table showing FTE allocation per user per project across 12 months. Managers see at a glance whether teams are over-allocated, under-utilized, or balanced. The matrix supports both Plan (what was budgeted) and Actual (computed from real worklogs) views, with variance highlighting that turns red when actuals deviate significantly from plan.

Clicking any cell drills down to the underlying worklogs — the exact hours that engineer logged on that project in that month. This eliminates the "the numbers don't add up" conversations that plague spreadsheet-based resource tracking.

  • Handles hundreds of users and hundreds of projects in a single interactive view
  • Color-coded variance heatmap: green (on-plan), amber (minor deviation), red (significant mismatch)
  • Fullscreen mode for planning meetings and projector display
  • TBD position tracking for future hires and open headcount
  • Optimized queries: pivot table renders in 15-100ms even at full scale (1000x improvement over initial)
3

Automatic Cost Bucket Classification

Purpose: Eliminate manual cost categorization and ensure every engineering hour is correctly allocated to the right GL account.

Every worklog entry is automatically classified into one of four cost buckets that map directly to the company's General Ledger structure. This classification determines whether the work is capitalizable (DIRECT_PRODUCT, DIRECT_PROJECT) or expensed (INDIRECT, OVERHEAD) — a distinction worth millions of dollars annually across the EUV Program.

The classification engine uses 30+ priority-ordered rules that examine user context (department, role), project context (type, category, funding entity), and activity code. Each entry gets a confidence score. Entries below 70% confidence are flagged for manual review by financial managers, ensuring exceptions are caught without burdening the majority of straightforward cases.

  • DIRECT_PRODUCT (GL-1000): Target 60-70% — capitalizable NPI/ETO engineering work
  • DIRECT_PROJECT (GL-1100): Target 10-15% — capitalizable project support (CEP, functional)
  • INDIRECT (GL-2000): Target 15-20% — non-capitalizable operational work
  • OVERHEAD (GL-3000): Target <10% — admin, training, PTO, hiring activities
  • 15 activity codes: DESIGN, TEST, DOC, RELEASE, MEET, REVIEW, PLAN, FIELD, SALES, SUSTAIN, TRIAGE, ADMIN, TRAINING, HIRING, PTO
  • Triggered on every worklog INSERT and UPDATE — classification always reflects current state
4

Inter-Company Recharge Automation

Purpose: Automate the billing of engineering hours between VSS, SUN, and LOCAL_KR entities so financial close is faster and more accurate.

Edwards' EUV Program spans multiple legal entities that bill each other for shared engineering resources. Previously, this reconciliation was a quarterly Excel exercise that consumed weeks of finance team effort and frequently contained errors. Operation Board automates the entire flow.

Each project is assigned a funding entity (BILLABLE, NON_BILLABLE, or INTERNAL) and mapped to specific Internal Order (IO) numbers per business unit. When an engineer in LOCAL_KR logs hours on a VSS-funded project, the platform automatically routes the cost to the correct recharge IO. Plan vs. Actual comparison shows billing variance in real time, not three months after the fact.

  • Configurable IO routing per business unit and project type
  • Auto-classify by project name/code patterns with manual override capability
  • Real-time plan vs. actual recharge comparison dashboard
  • Support for SHARED cost pools (cross-entity common infrastructure)
  • Export-ready reports for SAP GL reconciliation
5

Personal & Team Dashboard with AI Summaries

Purpose: Give every level of the organization — from individual contributor to executive — a relevant view of resource utilization.

The dashboard adapts to scope: personal (my work this week), sub-team (my direct reports), department (my org), or business unit (my division). Each scope shows weekly worklog summaries, FTE allocation breakdown, planned vs. actual comparison, and project timeline with PCP Gate milestones (G3/G5/G6).

AI-generated summaries distill a week of worklog data into a narrative paragraph highlighting key focus areas, anomalies, and trends. Managers who oversee 20+ engineers get a synthesized view instead of scrolling through hundreds of individual entries.

  • Multi-scope views: Personal, Sub-Team, Department, Business Unit
  • Weekly/monthly FTE breakdown by project and work type
  • AI summary generation with caching to minimize LLM API costs
  • Project milestone timeline with PCP Gate tracking
  • Work type distribution charts (Engineering, Design, Test, Documentation, Meetings)
6

Organization & Project Hierarchy Management

Purpose: Model the real organizational and project structure so that reports, permissions, and cost routing all follow the same taxonomy.

The platform maintains a dual hierarchy. The organization tree (Division → Department → SubTeam → JobPosition) determines reporting lines and dashboard scoping. The project tree (BusinessUnit → Program → Project → Milestone) determines cost routing and resource allocation targets. Both hierarchies are CRUD-managed through the admin UI.

  • Project types: PRODUCT (NPI/ETO), FUNCTIONAL (CEP), SUPPORT (standardized per BU)
  • Project lifecycle: Prospective → Planned → InProgress → OnHold → Completed/Cancelled
  • Milestone tracking with PCP Gate checkpoints (G3/G5/G6) and date targets
  • Filtering by status, business unit, funding entity, and project type
  • Automatic BU-specific support project generation for standardized overhead categories

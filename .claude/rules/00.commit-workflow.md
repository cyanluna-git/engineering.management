# Git & Commit Conventions

## Branch Naming

`feature/{short-description}` or `fix/{short-description}`

## Commit Format (Conventional Commits)

```
<type>(<scope>): <subject>
```

### Types
feat | fix | refactor | perf | test | docs | style | chore | ci

### Scopes
auth, worklog, resource, project, user, dashboard, api, db, deploy

### Subject Rules
- Imperative mood: "add", not "added"
- Lowercase first letter, no period, max 50 chars
- Reference issues in footer: `Closes #42`

### Examples
```
feat(auth): add JWT token refresh endpoint
fix(worklog): handle null user_id in resource plan
refactor(api): extract pagination logic to dependency
```

## PR Checklist
- [ ] Tests pass (`pytest`, `pnpm test:e2e`)
- [ ] No console errors/warnings
- [ ] Documentation updated if needed
- [ ] No secrets committed

Overview

Introduction

This document provides a step-by-step guide on the hardware and software used to recover controller issues such as network disconnection, ping loss, and file upload errors.

The recovery process involves diagnosing the issue, and if the Digi module memory is found to be corrupted, using tools such as ESP and JTAG programmers to reflash the module.

Critical — Memory Protection

The last 64 KB of flash memory contains unique configuration data including the MAC address. This block must be excluded from overwriting. Destroying it makes the PLC permanently unusable.

After recovery, settings must be reset in the ATE environment (e.g., switching from static IP to DHCP).

Section 2

Recovery Procedure

The recovery procedures for Type 1 and Type 2 systems are identical.

  • Diagnosis is first attempted via the ESP program
  • If ESP Flash Memory step fails → forced reinitialization using J-Flash & PuTTY
  • After J-Flash → return to ESP connection and upload firmware & T5.cod

If options are misconfigured, the final memory region will also be erased — making the PLC permanently unusable.

  • Target → Production Programming (F7)

Recovery — Step 3

PuTTY Serial Monitoring

Monitor boot status and interact with the Digi module via serial communication.

  • Monitor boot status — verify boot, FTP activation, network init
  • Console commands — MAC address modification, factory reset
Precondition

Connect RJ12 cable to COM3 on PLC. Check Device Manager → Ports. If not recognized, install FTDI driver (CDM2123620_Setup).

Device Manager — COM port recognition
a

"FTP download server is ready" → success → Close PuTTY
"FTP download server is ready" = successful reset
f
Return to Step 1, step e (Abatement) → re-upload firmware
Summary

Post-Recovery Checklist

  • Verify T5.cod file is present via File Management
  • Confirm controller boots normally without J-Link connected
  • Check PLC connection at 192.168.2.200
  • Disconnect J-Link module after final reboot
  • If ATE environment — switch from static IP to DHCP
Recovery Time

A standard recovery takes 10–20 minutes. Cases requiring J-Flash (Step 2) may take slightly longer.

Type 1 & Type 2
복구 프로세스

ESP, JTAG, PuTTY 도구를 사용해 네트워크 단절, ping 손실, 파일 업로드 오류가 발생한 컨트롤러를 진단하고 복구하는 단계별 가이드입니다.

개요

소개

이 문서는 네트워크 단절, ping 손실, 파일 업로드 오류와 같은 컨트롤러 문제를 복구할 때 사용하는 하드웨어와 소프트웨어 절차를 단계별로 설명합니다.

복구 절차는 먼저 문제를 진단하고, Digi 모듈 메모리 손상이 확인되면 ESP와 JTAG 프로그래머 같은 도구로 모듈을 다시 플래시하는 방식으로 진행됩니다.

중요 — 메모리 보호

플래시 메모리의 마지막 64 KB에는 MAC 주소를 포함한 고유 설정 데이터가 저장되어 있습니다. 이 영역은 덮어쓰기 대상에서 반드시 제외해야 하며, 손상되면 PLC를 영구적으로 사용할 수 없게 됩니다.

복구 후에는 ATE 환경에서 설정을 다시 맞춰야 합니다. (예: static IP에서 DHCP로 전환)

섹션 2

Recovery 절차

Type 1과 Type 2 시스템의 복구 절차는 동일합니다.

  • 먼저 ESP 프로그램으로 진단을 시도합니다.
  • ESP Flash Memory 단계가 실패하면 J-Flash & PuTTY로 강제 재초기화를 수행합니다.
  • J-Flash 완료 후에는 ESP 연결 단계로 돌아가 펌웨어와 T5.cod를 업로드합니다.

프로그램 및 검증 성공

J-Flash v5.10I 초과 버전인 경우:

중요 경고

옵션을 잘못 설정하면 마지막 메모리 영역까지 함께 삭제되어 PLC를 영구적으로 사용할 수 없게 됩니다.

  • 대상 장비 → Production Programming (F7)
  • Erase: "affected sectors"만 사용 ("Erase chip" 금지)
  • Program: 체크 / Verify: 선택
J-Flash v8 — 올바른 설정의 Production Programming
Erase는 "affected sectors"만 사용 — 전체 삭제 금지
절대 하지 말 것
  • 절대 "All Sector Erase" 또는 "Erase chip" 사용 금지
  • 마지막 64KB 블록의 MAC 주소와 시리얼 ID가 영구 손상됩니다.
Recovery — Step 3

PuTTY 시리얼 모니터링

부팅 상태를 모니터링하고 시리얼 통신으로 Digi 모듈과 상호작용합니다.

  • 부팅 상태 모니터링 — 부팅, FTP 활성화, 네트워크 초기화 확인
  • 콘솔 명령 — MAC 주소 수정, 공장 초기화
사전 조건

RJ12 케이블을 PLC의 COM3에 연결합니다. Device Manager → Ports에서 확인하고, 인식되지 않으면 FTDI 드라이버(CDM2123620_Setup)를 설치합니다.

최종 점검

복구 후 체크리스트

  • File Management에서 T5.cod 파일 존재 여부 확인
  • J-Link 없이도 컨트롤러가 정상 부팅되는지 확인
  • 192.168.2.200에서 PLC 연결 확인
  • 최종 재부팅 후 J-Link 모듈 분리
  • ATE 환경이면 static IP에서 DHCP로 전환
복구 시간

일반적인 복구는 10~20분 정도 소요됩니다. J-Flash(2단계)가 필요한 경우 더 오래 걸릴 수 있습니다.
